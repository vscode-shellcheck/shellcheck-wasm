# Domain docs

This repository uses a single-context layout.

- Read `CONTEXT.md` at the repository root for the domain glossary and vocabulary.
- Read relevant records in `docs/adr/` when a task touches an established architectural decision.
- Add new ADRs under `docs/adr/` only for decisions that are hard to reverse, surprising to a newcomer, and involve a real trade-off.
- Keep implementation plans under `docs/plans/`.
- When terminology conflicts with generic wording, use the terms defined by `CONTEXT.md`.
